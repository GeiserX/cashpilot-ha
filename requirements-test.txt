# aiohttp 3.14.0 made ClientResponse.__init__ require a keyword-only
# stream_writer arg, which aioresponses does not pass. Cap below 3.14 until
# aioresponses ships a compatible release.
#
# RE-CHECKED 2026-08-06 against aioresponses 0.7.9 (released 2026-06-23, i.e.
# AFTER this cap was written): STILL BROKEN. Verified by running it, not by
# reading the metadata --
#
#   TypeError: ClientResponse.__init__() missing 1 required keyword-only
#              argument: 'stream_writer'
#
# Note 0.7.9 DECLARES `aiohttp<4.0,>=3.8`, so its own metadata claims 3.14
# support and a version-range check would wave it through. Only running it
# shows otherwise.
#
# ON THE DEPENDABOT ALERTS (GHSA-cq5v-8q36-5273 and two mediums, all aiohttp):
# they land here, on a TEST-ONLY pin, and there is no exposure through it. The
# advisory is a DoS in the C response parser triggered by a malformed response
# from a server; under aioresponses every response is generated by the mock, so
# there is no untrusted server to send one.
#
# The RUNTIME is unaffected and is not capped: manifest.json asks for
# `aiohttp>=3.9.0` and Home Assistant supplies the actual version -- confirmed
# 3.14.3, the patched release, on the reference install. Raising that floor
# would be wrong: HA owns aiohttp and pins it tightly, so forcing an upgrade
# from a custom component can break HA itself.
